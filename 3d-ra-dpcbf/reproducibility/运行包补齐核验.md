# 运行入口与初版运行包补齐

[返回研究首页](../README.md) · [复现状态](版本与复现状态.md) · [来源清单](来源与校验清单.csv) · [路径适配](路径适配清单.csv)

本轮只处理实际的入口、文件依赖和启动清理问题。没有更改控制公式、QP、方法参数、种子、旧结果或录像，没有运行科学仿真。

## 修复了什么

| 问题 | 处理 |
|---|---|
| MA到输出目录找配置，计算后才发现缺文件 | 补回原配置，固定绑定输入根目录，在开始计算前读取 |
| RA相对输出检查与实际落盘位置不同 | 四方法统一绝对输出根目录；原子创建，已存在则拒绝覆盖 |
| 基线结果场景标签写死 | 从入口传入的实际场景标识读取 |
| C03依赖历史绝对目录 | 补回原绑定、原QP接口、原场景及协议，提供独立手动单例，包内相对SHA校验 |
| D82初版录像旁只有D89运行链 | 新增独立`first36/runtime`，原源码、三场景、冻结配置与原固件分别绑定 |
| PX4启动失败遗留日志配置和世界软链接 | 先检查依赖，再准备本次文件；启动失败和退出异常也执行恢复，外部路径及并发改动保留并报错 |
| CPU核号依赖旧机器测试文件 | 改为显式本机CPU选择，保留原隔离规则，不沿用旧核号 |
| 缺场景或初始化文件在启动后暴露 | 入口新增只检查模式；缺文件在导入飞行引擎前停止。原D82不用初始化，不借用其他阶段参数 |

## 核验到哪一步

- **8项基础设施测试通过。** 使用临时文件、假后端和假进程，覆盖四方法相对路径、已有结果保护、缺固件/启动异常连续两次恢复、退出回执异常、缺场景/初始化及CPU重复读取。Windows临时软链接操作使用模型，未冒充Linux真实启动。
- **四种数值入口检查通过。** 读取保存场景和配置，确认最终绝对输出位置；没有计算控制。
- **C03七组真实导入和配置检查通过。** 使用隔离目录中的冻结版本依赖，没有改变原Anaconda或其他仿真环境；不实例化控制器、不求解QP。
- **两套PX4帮助入口检查通过。** 帮助和只检查入口延迟导入飞行引擎。本机缺Linux/Gazebo时会明确报出，不能把这种预期拒绝写成目标平台通过。
- **原件保护通过。** 原6000次、100次、代表片、全部媒体、原冻结控制器和参数逐SHA保持不变。两套PX4计算主循环的AST与各自原件一致，仅初始化文件的路径绑定例外；MA/Park/C3BF去除声明的配置读取/场景标签改动后，计算AST与修改前一致。
- **补回105项原源码、场景与配置。** 发布副本中的路径匿名化和启动适配逐项登记；原来源SHA与发布SHA分开保留。原固件另以无损压缩保存，解压SHA与初版36份原回执全部一致。

## 仍然不能声称什么

没有重新运行数值案例、C03、36次或100次PX4。没有在目标Linux重新编译插件、重建相同SHA的PX4固件或执行SITL闭环，因此不声称“全库一键运行已经实测通过”或“硬实时已经保证”。上游PX4、Gazebo、rootfs、模型和系统依赖仍需按[初版准备说明](../px4-gazebo/first36/README.md)安装并检查。

初版D82、四障碍D65和后期D83/D89成绩继续分开，原历史停止、失败和预算超限记录不变。首页精简重复展示，16项全宽原片和100项完整媒体索引仍保留。
